# HASI Market — реализация ТЗ 0.1

## Роли
| Роль | Вход | Кабинет |
|---|---|---|
| Admin | /login | /admin → вкладка «Дилеры и склад» |
| Distributor | /login (создаёт админ) | /distributor/dashboard (склады, остатки — просмотр) |
| Dealer | /login (создаёт админ) | /dealer/dashboard |
| Customer | **аккаунта нет** | корзина и оформление без входа |

Защита: `proxy.ts` (по подписанному JWT) + `requireRole()` на страницах (роль и блокировка из БД) + `requireDealer()/requireAdmin()` в API.

## Поток заказа
1. Покупатель: каталог → корзина (localStorage) → `/checkout` (имя, телефон, адрес/комментарий) → `POST /api/orders`.
2. Заказ получает номер `HM-YYMMDD-XXXXXX`, статус `pending_dealer` → «Свободные заявки».
3. Дилер нажимает «Принять заявку» → `POST /api/dealer/orders/:id/claim`. Атомарный `UPDATE … WHERE status='pending_dealer' AND dealerId IS NULL` — выигрывает первый, остальные получают 409.
4. «Забрать товар со склада» → `POST /api/dealer/orders/:id/issue` (одна транзакция): проверка лимита `доступный = лимит − Σ незакрытых выдач`, проверка и списание остатка центрального склада, запись `stock_movements`, `sales`, `commissions` (3% дилер / 7% HASI, статус pending).
5. «Сообщить об оплате» → `POST /api/dealer/orders/:id/payment` (наличные/перевод) → `settlements` (pending).
6. Админ подтверждает: `POST /api/admin/hasi/settlements/:id {action:"confirm"}` → продажа закрыта (лимит освобождён), комиссии → `available`, заказ → `completed`. Выплата дилеру: `POST /api/admin/hasi/dealers/:id/payout`.

## Таблицы (lib/db/schema.ts)
users (+status), dealer_identity, distributors, warehouses, products, offers_stock, dealer_limits, stock_movements, customer_orders, order_items, sales, settlements, commissions. Создаются автоматически при первом обращении к БД (Turso или локальный файл). Центральный склад `hasi-central` и прайс-лист (`offers_stock`) заполняются из `products` автоматически.

## Настройки бизнес-правил
`lib/hasi-config.ts`: ставки 3% / 7%, базовый лимит 10 000 (меняется в админке и персонально для каждого дилера), наценка по умолчанию для закупочной цены (розница ÷ 1.10; правится на вкладке «Склад и прайс»).

## Ограничения
- Остаток центрального склада правьте на вкладке «Склад и прайс» (она синхронизирует витрину). Поле «остаток» в старой вкладке «Каталог» меняет только витрину.
- Дистрибьютор в этой версии — роль, склады и просмотр остатков; выдача идёт с центрального склада HASI.
- Паспортные данные хранятся в БД текстом. Перед боевым запуском рекомендуется шифрование на уровне приложения.

## Дополнение: паспорт-скан, CRUD дилеров, услуги и подкатегории

### Дилеры в админке (/admin → «Дилеры и склад», либо отдельная страница /admin/dealers)
- Создание и редактирование: email, телефон, ФИО, паспортные данные (номер, кем выдан, дата выдачи, адрес регистрации, дата рождения), лимит, статус (ожидает / активен / заблокирован), файл скана **PNG, JPG, WEBP или PDF до 4 МБ**.
- В таблице — превью скана (клик → полноэкранный просмотр; PDF открывается во встроенном просмотре). В окне редактирования — текущий скан и кнопка «Заменить фото».
- API: `GET/POST /api/admin/dealers`, `PATCH|PUT|DELETE /api/admin/dealers/:id`, `POST /api/admin/dealers/:id/payout`, `GET /api/admin/dealers/:id/passport`.
  Запросы создания/изменения принимают JSON либо multipart (`data` — JSON, `passportScan` — файл).
- **Где хранится скан.** Не в `public/uploads/passports/`: каталог `public` отдаётся без авторизации (любой, у кого есть ссылка, увидит паспорт), а на Vercel файловая система только для чтения. Файл хранится в БД (`dealer_identity.passportScanData`, BLOB), а в `passportScanUrl` лежит ссылка на защищённый эндпоинт, который отдаёт файл только администратору (`Cache-Control: private, no-store`). Тип файла проверяется по содержимому, а не по расширению.
- **Удаление.** Дилер без истории заявок удаляется полностью. Если история есть, аккаунт получает статус `deleted`: вход закрыт, email освобождён, скан стёрт, заявки и расчёты остаются для отчётности. Нельзя удалить дилера с незакрытыми заявками или невыплаченным балансом.

### Каталог
- `products.type` = `product | service`. Услуги (монтаж, прокладка кабеля…) имеют цену и описание, без остатка (на витрине всегда доступны), не выдаются со склада и не занимают лимит дилера.
- `categories.parentId` — два уровня. `/catalog?category=<slug>`: главная категория → плитки подкатегорий; подкатегория → товары; хлебные крошки «Главная / Каталог / Камеры / IP-камеры». `/category/<slug>` перенаправляет в каталог.
- Админка: «Управление категориями» — создание главных категорий и подкатегорий (выбор родителя), перенос, удаление (нельзя удалить категорию с подкатегориями или товарами).
